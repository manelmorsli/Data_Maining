Partie I — Panorama des stratégies de clustering

Introduction et définition du clustering

Le clustering (ou regroupement non supervisé) est une technique fondamentale du Data Mining qui consiste à partitionner un ensemble de données en groupes homogènes appelés clusters, de sorte que les objets à l’intérieur d’un même cluster soient similaires entre eux et dissemblables des objets des autres clusters. Contrairement à la classification supervisée, le clustering n’utilise pas d’étiquettes préalablement connues : il découvre la structure latente des données.

Définition formelle
Étant donné un ensemble de points X = {x₁, x₂, …, xₙ} dans un espace métrique muni d’une mesure de distance d(·,·), le clustering vise à trouver une partition C = {C₁, C₂, …, Cₐ} telle que la cohésion intra-cluster soit maximisée et la séparation inter-cluster soit maximisée.

Le clustering trouve des applications dans de très nombreux domaines : segmentation client en marketing, détection d’anomalies en cybersécurité, groupement de documents en TAL, analyse de gènes en bioinformatique, compression d’images, et bien sûr l’analyse épidémiologique illustrée dans ce projet.

Clustering par partitionnement

Les méthodes de partitionnement divisent les données en k groupes non-hiérarchiques, où k est un paramètre fixé à l’avance. Ces méthodes sont généralement itératives et optimisent une fonction objectif (souvent la somme des distances internes aux clusters).

K-Means Implémenté

Algorithme itératif qui assigne chaque point au centroïde le plus proche, puis met à jour les centroïdes comme la moyenne des points assignés.

Complexité : O(n·k·t·d) — n points, k clusters, t itérations, d dimensions
Avantages : rapide, simple, scalable
Limites : k fixé, sensible aux outliers, clusters sphériques uniquement, minimum local
K-Medoids (PAM) Robuste

Variante de K-Means où le représentant de chaque cluster est un point réel des données (medoïde) plutôt qu’une moyenne. Beaucoup plus robuste aux outliers.

Complexité : O(k(n−k)²) — plus lent que K-Means
Utilisation : données avec outliers, ou quand la moyenne n’a pas de sens (données catégorielles)
CLARANS Grandes données

Clustering Large Applications based on RANdomized Search. Version améliorée de PAM utilisant un échantillonnage aléatoire pour accélérer la recherche sur les grands jeux de données.

Complexité : O(n²)
Avantage : meilleure scalabilité que PAM pour grands datasets

Algorithme K-Means — Pseudo-code

  1. Choisir k centroïdes initiaux aléatoirement parmi les données
  2. Assigner chaque point au centroïde le plus proche (distance euclidienne)
  3. Recalculer chaque centroïde comme la moyenne de tous les points qui lui ont été assignés
  4. Répéter les étapes 2–3 jusqu’à convergence (centroïdes stables ou max_iters atteint)
Point de vigilance — Initialisation
K-Means est sensible à l’initialisation des centroïdes. Une mauvaise initialisation peut conduire à un minimum local. La méthode K-Means++ (scikit-learn par défaut) améliore l’initialisation en choisissant les centroïdes de façon à les écarter au maximum, réduisant considérablement la probabilité de converger vers un mauvais minimum.

Clustering hiérarchique

Les méthodes hiérarchiques construisent une structure arborescente (dendrogramme) représentant les relations d’emboîtement entre clusters. Elles ne nécessitent pas de spécifier k à l’avance : l’utilisateur découpe le dendrogramme au niveau souhaité après coup.

Fig. 1 — Les deux directions d’un clustering hiérarchique : agglomératif (Bottom-Up) et divisif (Top-Down)
Fig. 2 — Taxonomie complète des méthodes de clustering : Partitionnement, Hiérarchiques (Agglomératif/Divisif) et Densité
AGNES — Agglomerative Nesting Implémenté (Ward)

Approche Bottom-Up : démarre avec chaque point comme son propre cluster, puis fusionne itérativement les deux clusters les plus proches. La méthode de liaison Ward minimise l’accroissement de la variance interne lors de chaque fusion.

Liaisons : Ward · Complete · Average · Single · Centroid
Complexité : O(n² log n)
Avantages : pas de k requis, dendrogramme interprétable, robuste
DIANA — DIvisive ANAlysis Implémenté (Top-Down)

Approche Top-Down : démarre avec tous les points dans un seul cluster global, puis divise récursivement les clusters les moins cohésifs. Utilisé dans ce projet via cut_tree.

Complexité : O(n²)
Avantage : meilleur pour les grandes divisions au sommet de la hiérarchie
BIRCH Grandes données

Balanced Iterative Reducing and Clustering using Hierarchies. Construit un arbre CF (Clustering Feature) compact, puis applique un clustering sur ses feuilles. Conçu pour très grands datasets en mémoire limitée.

Complexité : O(n) — linéaire !
CURE Non-sphérique

Clustering Using REpresentatives. Représente chaque cluster par plusieurs points (pas juste un centroïde), permettant de détecter des clusters de formes arbitraires et de gérer les outliers.

Clustering basé sur la densité

Les méthodes basées sur la densité définissent les clusters comme des régions de haute densité de points, séparées par des régions de faible densité. Leur atout majeur est de détecter des clusters de formes arbitraires et d’identifier automatiquement les outliers.

DBSCAN Non-paramétrique

Définit deux paramètres : ε (rayon de voisinage) et MinPts (nombre minimum de voisins). Un point est core s’il a ≥ MinPts voisins dans son ε-voisinage. Les clusters sont les composantes connexes de core points.

Complexité : O(n log n) avec index spatial
Avantages : pas de k requis, détecte les outliers (label −1), formes arbitraires
Limite : difficile avec densités variables
OPTICS Densité variable

Extension de DBSCAN qui gère les clusters de densités variables. Produit un graphe de réachtabilité permettant d’extraire des clusters à différents niveaux de densité.

DENCLUE Estimateur de densité

DENsity-based CLUstEring. Basé sur l’estimation par noyaux (kernel density estimation). Définit les clusters comme des régions autour des maxima locaux de la fonction de densité estimée.

Quand utiliser DBSCAN ?
DBSCAN est idéal quand vous ne connaissez pas le nombre de clusters, que vos données ont des formes non sphériques (demi-lunes, anneaux, spirales), ou quand vous voulez détecter des anomalies (les points étiquetés −1 sont des outliers). En revanche, il ne fonctionne pas bien si les clusters ont des densités très différentes ou en haute dimension (malédiction de la dimensionnalité).

Clustering basé sur les modèles

Ces méthodes supposent que les données ont été générées par un mélange de distributions probabilistes. Chaque cluster correspond à une composante du mélange. L’algorithme EM (Expectation-Maximization) est utilisé pour estimer les paramètres.

GMM — Gaussian Mixture Models Probabiliste

Modélise les données comme un mélange de k gaussiennes. Chaque point a une probabilité d’appartenance à chaque cluster (soft assignment). Les paramètres (μ, Σ, π) sont estimés par EM.

Avantages : clusters ellipsoïdaux, assignation douce, généralise K-Means
Limite : suppose la normalité, plus coûteux que K-Means
Python : sklearn.mixture.GaussianMixture

Lien entre K-Means et GMM

K-Means est un cas particulier de GMM où toutes les gaussiennes ont la même covariance isotropique (sphérique) et l’assignation est dure (0 ou 1). En ce sens, GMM est une généralisation probabiliste de K-Means, permettant des clusters ellipsoïdaux et des frontières souples.

Clustering spectral

Le clustering spectral s’appuie sur les vecteurs propres (spectres) du Laplacien du graphe de similarité des données. Il est particulièrement efficace pour des structures de données complexes que les méthodes traditionnelles ne peuvent pas capturer.

Spectral Clustering Graphes
  1. Construire un graphe de similarité (ex. k-NN ou noyau gaussien)
  2. Calculer le Laplacien normalisé L = D⁻½(D−W)D⁻½
  3. Extraire les k vecteurs propres associés aux plus petites valeurs propres
  4. Appliquer K-Means dans l’espace des vecteurs propres

Avantage : détecte des clusters non convexes, efficace pour les graphes
Limite : O(n³) — ne scale pas aux très grands datasets
Python : sklearn.cluster.SpectralClustering

Implémentation personnalisée (algorithme TD)

Une implémentation K-Means from scratch a été réalisée en Python natif pour comprendre les mécanismes internes de l’algorithme. 

def kmeansTD(data, K, max_iters=100):
    # Initialisation aléatoire des centroïdes
    centroids = data[np.random.choice(data.shape[0], K, replace=False)]

    for _ in range(max_iters):
        # Distances et assignation
        distances = np.linalg.norm(data[:, np.newaxis] - centroids, axis=2)
        clusters = np.argmin(distances, axis=1)

        # Recalcul des centroïdes
        new_centroids = np.array([
            data[clusters == k].mean(axis=0) for k in range(K)
        ])

        if np.all(centroids == new_centroids):
            break
        centroids = new_centroids

    return clusters, centroids

Limitation — Données binaires et K-Means
K-Means calcule des moyennes de centroïdes, ce qui n’est pas naturel pour des données binaires. Pour des données binaires, K-Modes ou K-Prototypes sont plus appropriés car ils utilisent le mode plutôt que la moyenne.

Prétraitement et alignement temporel

import pandas as pd
from sklearn.preprocessing import MinMaxScaler

# Alignement sur la plage temporelle commune à tous les pays
data['dateRep'] = pd.to_datetime(data['dateRep'], format='%d/%m/%Y')

start_dates = data.groupby('countriesAndTerritories')['dateRep'].min().max()
end_dates   = data.groupby('countriesAndTerritories')['dateRep'].max().min()
aligned_data = data[(data['dateRep'] >= start_dates) & (data['dateRep'] <= end_dates)]
# Plage commune : 2020-03-14 → 2022-10-12

# Normalisation Min-Max + agrégation par pays
def normalize_column(column):
    scaler = MinMaxScaler()
    return scaler.fit_transform(column.values.reshape(-1, 1)).flatten()

aligned_data['cases_normalized']  = normalize_column(aligned_data['cases'])
aligned_data['deaths_normalized'] = normalize_column(aligned_data['deaths'])

country_totals = aligned_data.groupby('countriesAndTerritories').agg({
    'cases_normalized' : 'sum',
    'deaths_normalized': 'sum'
}).reset_index()
country_totals.columns = ['countriesAndTerritories', 'total_cases', 'total_deaths']
country_totals['cases_deaths_sum'] = country_totals['total_cases'] + country_totals['total_deaths']
Fig. 11 — Population ajustée par pays sur la période d’analyse, justifiant la nécessité de la normalisation avant clustering
Pourquoi la normalisation Min-Max ?
Sans normalisation, les grands pays (France, Allemagne) domineraient le clustering par leur seule taille. La normalisation ramène les valeurs dans [0, 1], mettant tous les pays sur un pied d’égalité.

Approche agglomérative Bottom-Up (Ward)

from scipy.cluster.hierarchy import dendrogram, linkage, fcluster

linkage_matrix = linkage(country_totals[['cases_deaths_sum']], method='ward')

plt.figure(figsize=(15, 10))
dendrogram(linkage_matrix, labels=country_totals['countriesAndTerritories'].values)
plt.title("Dendrogramme Bottom-Up (Ward)")
plt.show()

# Seuil automatique = moitié de la distance max
seuil = linkage_matrix[:, 2].max() / 2
country_totals['cluster'] = fcluster(linkage_matrix, t=seuil, criterion='distance')

# Clustering sur cas seuls et décès seuls
for col, label in [('total_cases', 'cluster_cases'), ('total_deaths', 'cluster_deaths')]:
    lm = linkage(country_totals[[col]], method='ward')
    country_totals[label] = fcluster(lm, t=lm[:, 2].max() / 2, criterion='distance')
Comment lire un dendrogramme ?
L’axe Y représente la distance de fusion. Plus la barre est haute, plus les clusters fusionnés sont dissemblables. Pour choisir k, cherchez le plus grand saut vertical et tracez une ligne horizontale à cette hauteur.

Approche divisive Top-Down

from scipy.cluster.hierarchy import cut_tree

# Même matrice, lue de haut en bas
plt.figure(figsize=(15, 10))
dendrogram(linkage_matrix, labels=country_totals['countriesAndTerritories'].values)
plt.title("Dendrogramme Top-Down")
plt.gca().xaxis.tick_top()
plt.show()

# Découpage en k=4 clusters
country_totals['cluster'] = cut_tree(linkage_matrix, n_clusters=4).flatten()

for c in country_totals['cluster'].unique():
    pays = country_totals[country_totals['cluster'] == c]['countriesAndTerritories'].tolist()
    print(f"Cluster {c}: {pays}")
Différence clé Bottom-Up vs Top-Down
Bottom-Up (AGNES/Ward) : chaque pays commence seul, les plus proches fusionnent. Seuil automatique.
Top-Down (DIANA) : on part d’un cluster global et on divise. k=4 spécifié via cut_tree.
Les deux utilisent la même matrice Ward, mais la direction de lecture change le sens de l’analyse.

Partie IV — Conseils pratiques & Approfondissements

Choisir le bon algorithme

Arbre de décision — Choisir son algorithme
1. Connaissez-vous le nombre de clusters ?
   → Oui : K-Means, K-Medoids, GMM, Spectral
   → Non : DBSCAN, OPTICS, Clustering hiérarchique

2. Quelle est la forme attendue des clusters ?
   → Sphérique : K-Means    → Ellipsoïdale : GMM    → Arbitraire : DBSCAN, Spectral

3. Quel est l’ordre de grandeur du dataset ?
   → < 10k : tous les algorithmes
   → 10k–1M : K-Means, DBSCAN, BIRCH
   → > 1M : Mini-Batch K-Means, BIRCH

4. Y a-t-il des outliers ?
   → Oui : K-Medoids, DBSCAN    → Non : K-Means, AGNES

Déterminer K optimal — Elbow & Silhouette

Méthode du coude (Elbow Method)

from sklearn.cluster import KMeans

inertias = []
K_range = range(1, 11)
for k in K_range:
    km = KMeans(n_clusters=k, random_state=42, n_init=10)
    km.fit(data_for_clustering)
    inertias.append(km.inertia_)

plt.plot(K_range, inertias, marker='o')
plt.xlabel('k') ; plt.ylabel('Inertie (WCSS)')
plt.title('Méthode du coude') ; plt.show()

Score de silhouette

from sklearn.metrics import silhouette_score

silhouette_scores = []
for k in range(2, 11):
    km = KMeans(n_clusters=k, random_state=42, n_init=10)
    labels = km.fit_predict(data_for_clustering)
    silhouette_scores.append(silhouette_score(data_for_clustering, labels))

plt.plot(range(2, 11), silhouette_scores, marker='s', color='darkorange')
plt.title('Score de silhouette en fonction de k') ; plt.show()

Pièges courants et bonnes pratiques

Piège 1 — Oublier de normaliser
Si les features ont des échelles très différentes, K-Means sera dominé par la feature à grande échelle. Toujours normaliser (StandardScaler ou MinMaxScaler) avant d’appliquer un clustering.
Piège 2 — Confondre cluster et classe
Les clusters obtenus ne correspondent pas nécessairement aux classes réelles. L’ARI (Adjusted Rand Index) permet de mesurer la correspondance si les étiquettes sont disponibles.
Piège 3 — Haute dimensionnalité
En haute dimension, les distances euclidiennes deviennent quasi-uniformes. Appliquer PCA, UMAP ou t-SNE avant le clustering, pas seulement pour la visualisation.
Pipeline de validation recommandé
  1. Explorer les données : distributions, corrélations, valeurs manquantes
  2. Prétraiter : imputation, normalisation, réduction dimensionnelle
  3. Tester plusieurs algorithmes et plusieurs valeurs de k
  4. Évaluer : Elbow, Silhouette, Davies-Bouldin
  5. Interpréter les clusters (profiling, visualisation)
  6. Valider avec un expert du domaine si possible

Extensions et perspectives

Améliorations immédiates de ces projets

  • K-Means : Ajouter la méthode du coude et le score de silhouette pour justifier k=3 ou k=5 ; appliquer K-Modes pour données binaires
  • K-Means : Comparer avec DBSCAN pour vérifier la présence d’outliers dans le dataset d’intérêts
  • Hiérarchique : Tester différentes méthodes de liaison (complete, average) ; calculer le score de silhouette pour valider le seuil
  • Hiérarchique : Enrichir les features avec le taux d’incidence (cas/population) pour une comparaison plus équitable
  • Les deux : Utiliser UMAP au lieu de PCA pour des visualisations 2D plus fidèles

Pistes d’approfondissement

  • Clustering temporel : Appliquer le clustering sur les séries temporelles COVID-19 directement (distance DTW)
  • Semi-supervisé : Exploiter les étiquettes partielles dans un Constrained K-Means
  • Interprétabilité : Utiliser des Shapley Values pour expliquer l’appartenance à un cluster
  • Déploiement : Packager le clustering dans une API REST (FastAPI) pour segmentation en temps réel
  • AutoML : Explorer auto-sklearn ou pycaret pour automatiser la sélection d’algorithme
